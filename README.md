## 它是什么

微信 4.x 桌面版改用 Qt 自绘渲染，不再暴露 UI Automation 节点，导致老牌方案
[wauto](https://github.com/cluic/wxauto) 那套「读 UIA 树」的做法彻底失效。

上游项目 [wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica)
解决了底层问题（**本地 SQLCipher 数据库解密**读消息 + **UIA/OCR 混合驱动**发消息），
但它是一个**库**。本项目是在它之上的一层**完整应用**：

| | wechatauto-replica（上游库） | 本项目 |
|---|---|---|
| 形态 | Python 库 + demo 脚本 | 单文件 GUI 程序 |
| 读消息 | `WeChatDB` / `Listener` | 监听 + 去重 + 触发规则 + 冷却 |
| 发消息 | `WeChatGUI.send_msg` | 发送队列 + 节流 + 失败回退（不丢消息） |
| **群昵称** | 未暴露 | ✅ 从 `chat_room.ext_buffer` 解出群名片，@ 才找得到人 |
| **@ 群成员** | `at_member`（OCR+坐标，实测弹层不出现） | ✅ 走 UIA，稳定可用 |
| 大模型 | 无（要自己写） | 任意 OpenAI 兼容接口 + 多轮上下文 |
| 记忆 | 无 | 三层：滑动窗口 / 跨重启持久化 / 长期人物画像 |
| 人物规则 | 无 | 按群昵称/备注/wxid 认人 → 忽略 / 仅关键词 / 仅@ / 专属人设 |
| 提示词 | 无 | 预设一键切换，运行中即时生效 |

## 功能

### 收发

- **读消息**：本地数据库直接解密读取（**不依赖微信在前台**），全量历史可导出
- **实时监听**：增量轮询，每条新消息在独立会话线程处理（会话内保序、跨会话并行）
- **发消息**：文本 / 文件 / 图片 / 回复 / **@ 群成员** / 引用消息
- **@ 群成员**：用**群昵称**（群名片）@ 人 —— 见[技术点](#几个反直觉的技术点)
- 撤回最近消息、拍一拍、发起语音/视频通话

### 智能回复

- 任意 **OpenAI 兼容接口**（DeepSeek / OpenAI / 通义 / Kimi / 硅基流动 / 本地 Ollama…）
- **私聊与群聊分别设规则**：全部回复 / 仅关键词 / **仅 @我** / 不回复
- **人物规则**：认出特定的人给特定回应（拉黑、只回关键词、只被@才回、换专属人设）
- **提示词预设**：内置多套人设，一键切换，**运行中即时生效**
- **发送队列**：单线程串行 + 节流，避免 GUI 操作打架

### 记忆（三层）

| 层 | 内容 | 特性 |
|---|---|---|
| ① 短期 | 对话滑动窗口 | 纯内存、按会话隔离、每会话上限 200 条 |
| ② 持久化 | 对话历史落盘 | **重启不失忆**，原子写，超期自动过期 |
| ③ 长期 | 人物画像（谁是谁/喜好/约定） | 由模型自动抽取，注入每次回复 |

再加**启动回填**：启动时直接读数据库里已有的聊天记录，**一上线就认识对方**，
不必等重新聊几句。

### 界面

- tkinter 单窗口，全部配置在界面上完成，配置持久化到 JSON
- 消息记录 + 运行日志双视图，统计分析（收到/回复/已发送/跳过/错误/档案）
- 「更新昵称」一键重读群昵称与备注（平时缓存 120 秒）
- 记忆与档案可查看、可单独清除

## 环境要求

- **Windows 10/11**（依赖 Win32 API、UIA、Windows OCR）
- **Python 3.9+**（实测 3.12 / 3.13；**必须 64 位**，要和微信位数一致）
- **微信 4.x 桌面版，已登录**
- 大模型 API Key（任意 OpenAI 兼容服务）

> **发送需要微信窗口可见。** 读消息不需要（直接读数据库），但发消息是 GUI 自动化：
> 微信最小化会被自动恢复，**关到托盘则必须手动点托盘图标**，锁屏/息屏会失败。

**务必先 `cd` 到项目目录再启动**（上游库的日志目录是相对工作目录的，虽然程序会自动纠正，
但先 cd 更稳妥）：

```bat
cd /d 你的项目目录
python wx_ai_bot.py
```

界面上按顺序操作：

1. **测试微信** —— 确认微信 4.x 已登录、主窗口可见
2. **载入会话列表** → 在「② 监听范围」里**直接点击**要监听的会话（再点一下取消）
3. **填写大模型 API** —— 地址 / Key / 模型名 / 系统提示词
4. **测试大模型** —— 确认连通，避免启动后才发现密钥写错
5. **启动机器人**

复制 `wx_ai_bot_config.example.json` 为 `wx_ai_bot_config.json` 再填自己的值；

> `wx_ai_bot_config.json`、`wx_ai_bot.log`、`wx_ai_bot_memory.json`、

## 界面说明

| 分组 | 要点 |
|---|---|
| **① 微信连接** | 账号选择、载入会话列表、**更新昵称** |
| **② 监听范围** | 全部会话 / 指定会话（点击即选中，可多选；有全选/清空；实时显示「已选 N 个」） |
| **③ 大模型 API** | 地址 / Key / 模型 / **提示词预设** / 温度 / tokens / 超时 |
| **④ 回复规则** | 私聊与群聊分别设模式、关键词、上下文轮数、冷却、隔离方式、回填、记忆、@对方 |
| **⑤ 人物规则** | 认人 → 特定处理；列表从上到下第一个命中生效 |

### 人物规则怎么写

| 字段 | 说明 |
|---|---|
| 对象 | 群昵称 / 备注 / 微信昵称 / wxid；多个用逗号分隔；`*` 为兜底 |
| 范围 | 全部 / 仅群聊 / 仅私聊 / 指定群（填群 wxid、`group:xxx` 或群名） |
| 处理 | 正常回复 / **忽略不回复** / 仅关键词 / 仅被@ |
| 专属提示词 | 追加到全局提示词，或替换之 |

例子：

- **拉黑某人** → 对象 `某人`，处理「忽略不回复」
- **只回某人** → 对象 `张三` 范围「仅私聊」处理「正常回复」；再加兜底 `*` + 「忽略不回复」
- **对特定人换人格** → 对象 `李四`，专属提示词「用最简短的话回答，不要用网络用语」

## 工作原理

```
Listener（每 1 秒轮询解密后的数据库）
        │  新消息 → 每会话一条独立工作线程（会话内保序、跨会话并行）
        ▼
剥掉群消息正文前缀（wxid_xxx:\n正文）→ 真实发送者 wxid + 干净正文
        ▼
群昵称花名册（chat_room.ext_buffer）→ 解析出「谁在这个群里叫什么」
        ▼
人物规则匹配 → 忽略 / 仅关键词 / 仅@ / 换人设
        ▼
触发规则 + 冷却（群内按人分别计时）
        ▼
拼装 messages（系统提示词 + 长期画像 + 该会话历史上下文 + 本条）
        ▼
调用大模型（信号量限流、失败重试）
        ▼
发送队列（单线程串行 + 节流）
        ▼
UIA 发送（失败降级坐标 + OCR）
        ├─ 开了「@ 对方」：UIA 真实按键敲 @ → 读 chat_mention_list → 点成员
        └─ 任一步失败 → 回退普通发送，绝不丢消息
```

- 读取不需要微信前台；**发送必须是 GUI 操作**
- 耗时操作（解密、大模型、发送）都在后台线程，界面不卡
- 消息去重按 `(会话, 消息 id)`

## 几个反直觉的技术点

这些都是**实测**踩出来的，不是看文档猜的。细节见
[docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)。

### 1. 群里 @ 人必须用「群昵称」，不是微信昵称

微信群里 @ 某人时插入的是这个人**在该群的群昵称（群名片）**。
库里的 `contact.nick_name` 是全局昵称 —— 用它去 @ **永远找不到人**。

实测一个 55 人群：**45 人设了群名片，其中 45 人的群昵称与全局昵称完全不同**。

群昵称存在 `contact.db` 的 `chat_room.ext_buffer`（一个 protobuf），
上游库没有暴露，本项目自己解：

```
repeated f1 { f1: wxid, f2: 群昵称(可缺省), f3: flag, f4: 邀请人 }
```

群昵称为空时显示的是全局昵称（备注优先），与微信一致。

### 2. 「@我」检测也要用群昵称

否则机器人在某群改了名片就再也收不到 @ ——
实测机器人在两个不同群里的显示名可以完全不一样，
只用全局昵称判断会漏掉全部 @。

### 3. 上游的 `at_member` 走不通，本项目改用 UIA

`WeChatGUI.at_member()` 是 OCR + 坐标：注入一个 `@` 再截图找成员名。
实测**弹层根本不会出现** —— 它用 `type_unicode('@')` 注入 Unicode 字符，
微信不认为那是 @ 提及。而 `SendKeys('@')`（真实按键）会立刻弹出：

```
WindowControl  aid='MentionPopover'      class='mmui::XPopover'
  ListControl  aid='chat_mention_list'   class='mmui::XTableView'
    ListItemControl  name='某个成员'
```

所以本项目改成：真实按键敲 `@` → 从 UIA 树读成员名 → UIA 点击 → 校验 → 追加正文 → 回车。
全程不需要 OCR 和坐标。

### 4. 微信把 @ 提及渲染成 U+FFFC

点选成员后，输入框 `ValuePattern` 的值不是 `@名字`，而是 **U+FFFC**
（OBJECT REPLACEMENT CHARACTER，即内联「芯片」）。据此判断提及是否插入成功，
判断 `"@" in value` 会永远失败。

### 5. disabled 的 Listbox 会**静默吞掉**填充

Tk 的 `Listbox` 在 `state="disabled"` 时，`insert` / `delete` **不报错也不生效**。
所以「全部会话」模式下列表被禁用时点「载入会话列表」，看着成功其实一条都没进去，
切回「指定会话」后是个空列表。本项目在填充前先置 `normal`，填完再恢复。

### 6. 工作目录不可写会导致「无法发送」

上游库的日志目录是 `Path("wechatauto_logs")`（**相对当前工作目录**）。
从别处启动会在建目录时抛 `PermissionError [WinError 5]`。更麻烦的是它的
FileHandler 是**惰性创建**的，失败后 `file_handler` 仍为 `None`，
于是**每次日志调用都重抛**同一个异常 → 整个库瘫痪，
报错还会伪装成「微信窗口不可用」。本项目启动时先 `chdir` 到脚本目录，
并预探一次文件日志（失败就自动关掉它）。

### 7. 导入 wechatauto 前必须 flush

它会导入 colorama，colorama 在 Windows 上会用 `AnsiToWin32` **重新包装
`sys.stdout`**，此前未 flush 的输出会被整段丢弃
（表现为「输出重定向到文件时开头几行消失，交互式运行却正常」）。

### 8. `comtypes` 需要写代码缓存目录

`uiautomation → comtypes` 会往 `site-packages\comtypes\gen` 或 `%APPDATA%\Python`
写生成的模块。受限/只读环境下会 `PermissionError`，程序已把它翻译成可读提示。

## 记忆模型

### ① 短期（自动）

内存滑动窗口，按会话隔离（可选「群内按人隔离」）：

- 每会话上限 **200 条消息**（= 100 轮），超出丢弃最早的
- 实际带多少给模型由「上下文轮数」决定（默认 3 轮）
- `context_turns=0` 则不记录也不携带

### ② 持久化（默认开）

对话历史落盘 `wx_ai_bot_memory.json`，重启机器人不失忆：

- 后台线程按 30 秒节流写盘；点「停止」时强制写盘
- 最多 200 个会话（超出淘汰最久未更新的）
- 超过 7 天未更新的记忆视为过期
- 原子写，文件损坏只会被静默跳过

### ③ 长期人物画像（默认开）

由模型从对话中抽取**稳定的、长期有用**的信息（称呼/关系/喜好/约定/背景），
**明确排除**一次性寒暄、情绪、玩笑，以及敏感信息（证件号、密码、住址门牌、银行卡、精确生日）。

- 每人累计 N 条消息（默认 10）触发一次，两次抽取间隔 ≥ 30 分钟（双重节流）
- 抽取在独立线程跑，不阻塞回复
- 结果去重合并，每人上限 20 条
- 回复时注入系统提示词
- **以 wxid 为键**（昵称会变，wxid 不变），改过名字后旧名转入别名

### 启动回填（默认开）

启动时直接读数据库里已有的聊天记录（默认最近 20 条文本消息、72 小时内）：

- 自己发的是 `assistant`，对方发的是 `user`
- 群里剥掉 `wxid_xxx:\n` 前缀，并用**群昵称**标注说话人
- 相邻同角色消息合并，省 token
- **已有持久化记忆的会话不重复回填**
- 取样池会扩大 4 倍再筛（群里图片/表情多，只取 N 条原始消息可能筛不出几条文本）

> **成本提醒**：三层记忆都会增加每次请求的 token 数。嫌贵就把「启动回填」调小、
> 「每 N 条抽取」调大，或关掉长期记忆。

## 已知限制

1. **发送必须微信窗口可见** —— 最小化会自动恢复；**关到托盘只能手动点托盘图标**；锁屏/息屏必失败
2. **发送期间会抢占鼠标键盘**，一次约 1~36 秒（@ 走 OCR 兜底时更慢）
3. **微信升级可能失效** —— 热激活、控件名、数据库结构都是版本敏感的
4. **图片 AES 密钥是瞬态的** —— 只在你查看图片时驻留内存，找到后会被缓存
5. **群聊原图**需先在微信里打开过，否则只有缩略图
6. **视频**只在本地已有 mp4 时才能下载
7. **朋友圈发布**未实现（4.x 自绘界面，不可靠）
8. 撤回受微信自身 2 分钟限制

## 常见问题

**Q：启动报 `WinError 5 ... 'wechatauto_logs'`**
工作目录不可写。程序已自动切到脚本目录，若仍出现请务必先 `cd /d 项目目录` 再启动。

**Q：能收到消息但不回复 / 发送失败**
看「运行日志」里的报错。日志现在会区分「微信窗口不可见」「权限失败」「其他」，
不再一律说「微信窗口不可用」。

**Q：@ 群成员没生效**
先跑 `python tools/verify_at.py`（dry-run）看匹配结果。
它会打印每个成员的候选匹配名与失败原因。

**Q：群聊不回复**
默认群聊是「仅 @我 时回复」。检查「④ 回复规则」里的群聊模式。
日志里 `跳过（未被 @）` 说明规则生效。

**Q：提示「无法导入 wechatauto」**
`pip install -r requirements.txt`。`--check` 会告诉你缺哪个包。

**Q：读取数据库失败 / 密钥提取不到**
① 微信 4.x 已登录；② Python 与微信同为 64 位；③ 多账号时选对账号。
可用上游自带的 `python -m wechatauto.diagnose_keys` 获取细节。

## 隐私与安全

这个程序会读写你的**全部微信数据**。请务必了解：

- **明文文件**：`wx_ai_bot_config.json`（含 **API Key 明文**）、`wx_ai_bot.log`、
  `wx_ai_bot_memory.json`（对话历史）、`wx_ai_bot_profiles.json`（人物档案）
- **解密缓存**：`%TEMP%\wechatauto_db\<账号>\` 或项目下 `.wxdb_cache\`
  —— 这是你**聊天数据库的明文副本**
- 以上全部已在 `.gitignore` 中排除。**上传前请先跑**：

```bat
python tools/check_secrets.py
```

它会扫描 API Key 形态、wxid、手机号、邮箱、本机路径，以及被遗漏的敏感文件。

> ⚠️ **如果密钥已经 push 过**：即使删掉文件，密钥仍留在 git 历史里 ——
> 必须**立刻去服务商后台吊销并重新生成**。
