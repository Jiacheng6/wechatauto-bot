# 微信 AI 自动回复机器人

基于 [wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica) 的**图形化**微信自动回复工具：
本地数据库读消息 → 大模型生成回复 → UIA 驱动发出去。单文件、开箱即用。

**Windows 10/11 · Python 3.9+（64 位）· 微信 4.x**

> [!WARNING]
> 仅供**个人学习与自动化研究**。自动化微信客户端可能违反《微信软件许可及服务协议》，
> **存在账号被限制的风险**。请只用小号测试，不要用在主号、不要商用、不要做群发营销。

## 功能

**收发**
- 读消息走**本地 SQLCipher 数据库解密**，不需要微信在前台，可读全量历史
- 实时监听：增量轮询，每会话独立线程（会话内保序、跨会话并行）
- 发送：文本 / 文件 / 图片 / 回复 / **@ 群成员** / 引用消息
- @ 用**群昵称**（群名片），走 UIA 路径，不依赖 OCR

**智能回复**
- 任意 **OpenAI 兼容接口**（DeepSeek / OpenAI / 通义 / Kimi / 硅基流动 / 本地 Ollama…）
- 私聊与群聊**分别**设规则：全部回复 / 仅关键词 / **仅 @我** / 不回复
- **人物规则**：按群昵称/备注/wxid 认人 → 忽略 / 仅关键词 / 仅@ / 换专属人设
- 提示词预设一键切换，**运行中即时生效**
- 发送失败自动回退普通发送，**绝不丢消息**

**记忆（三层）**

| 层 | 内容 | 特性 |
|---|---|---|
| ① 短期 | 对话滑动窗口 | 内存，按会话隔离，上限 200 条 |
| ② 持久化 | 对话历史落盘 | **重启不失忆**，原子写，超期自动过期 |
| ③ 长期 | 人物画像（谁是谁/喜好/约定） | 模型自动抽取，注入每次回复 |

外加**启动回填**：启动时直接读库里已有的聊天记录，**一上线就认识对方**。

**界面**
tkinter 单窗口，全部配置在界面上完成；消息记录 + 运行日志双视图；「更新昵称」一键重读群昵称；记忆与档案可查看、可单独清除。

## 环境要求

- Windows 10/11（依赖 Win32 API、UIA、Windows OCR）
- Python 3.9+，**必须 64 位**（要和微信位数一致）
- 微信 4.x 桌面版，**已登录**
- 大模型 API Key

> **读消息不需要微信在前台；发消息需要窗口可见。**
> 最小化会自动恢复，**关到托盘必须手动点托盘图标**，锁屏/息屏会失败。

## 安装

```bat
git clone <this-repo>
cd <this-repo>
pip install -r requirements.txt
python wx_ai_bot.py --check
```

`requirements.txt` 会装好 `wechatauto-replica` 及其全部依赖（约 200MB）。
`--check` 逐项报告环境状态并给出补齐命令。

## 快速开始

**务必先 `cd` 到项目目录**（上游库的日志目录是相对工作目录的）：

```bat
cd /d 你的项目目录
python wx_ai_bot.py
```

界面上按顺序：**测试微信** → **载入会话列表**（在「② 监听范围」直接点击选中，再点取消）→ **填大模型 API** → **测试大模型** → **启动机器人**。

配置可以直接在界面上填（点「保存配置」生成 `wx_ai_bot_config.json`），
也可以复制 `wx_ai_bot_config.example.json` 再改。

## 几个反直觉的地方

详见 [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md)（12 条实测踩坑，含错误诊断的复盘）。

- **群里 @ 人必须用「群昵称」**，不是微信昵称。实测某群 45 人的群昵称与全局昵称 **100% 不同**，用全局昵称 @ 永远找不到人
- **「@我」检测也要用群昵称**，否则机器人在某个群改了名片就再也收不到 @
- 上游的 `at_member` 用 `type_unicode('@')` 注入字符，**微信不认为那是 @ 触发**，成员弹层根本不出现 —— 本项目改用真实按键 + UIA 读列表
- **微信把 @ 提及渲染成内联「芯片」**，输入框 `ValuePattern` 里是 `U+FFFC` 而不是 `@名字`
- **禁用状态的 Tk Listbox 会静默吞掉 `insert`**（不报错也不生效）
- **工作目录不可写**会让上游库的日志初始化失败，且报错会伪装成「微信窗口不可用」
- **导入 wechatauto 前必须 flush**，否则 colorama 重新包装 `sys.stdout` 会丢掉已缓冲的输出

## 诊断工具

`tools/` 下每个脚本都能独立运行：

| 脚本 | 用途 | 需登录微信 |
|---|---|---|
| `verify_read.py` | 读取链路：密钥提取 / 解密 / 读会话与消息 | ✅ |
| `verify_send.py` | 发送链路（默认 dry-run，`--yes` 才真发） | ✅ |
| `verify_at.py` | @ 群成员（默认 dry-run，`--send` 才真发） | ✅ |
| `verify_llm.py` | 大模型客户端（本地 mock，**不需要 API Key**） | ❌ |
| `verify_fallback.py` | 发送回退逻辑（@ 失败绝不吞消息） | ❌ |
| `verify_features.py` | 群昵称 / 人物规则 / 群聊隔离 / 提示词预设 | 部分 |
| `verify_memory.py` | 三层记忆 / 启动回填 / 昵称刷新 | 部分 |
| `verify_gui.py` | 界面级：真实控件上的多选交互与提示 | ❌ |
| `check_secrets.py` | **提交前防泄漏预检** | ❌ |

## 已知限制

1. 发送需要微信窗口可见，且运行期间会**抢占鼠标键盘**（一次 1~36 秒）
2. 微信升级可能失效（热激活、控件名、数据库结构都是版本敏感的）
3. 图片 AES 密钥是瞬态的（只在你查看图片时驻留内存）
4. 群聊原图需先在微信里打开过，否则只有缩略图
5. 视频只在本地已有 mp4 时才能下载
6. 朋友圈发布未实现（4.x 自绘界面，不可靠）
7. 撤回受微信自身 2 分钟限制

## 隐私与安全

这个程序会读写你的**全部微信数据**。以下文件含明文私密内容，**已在 `.gitignore` 中排除**：

```
wx_ai_bot_config.json      含 API Key 明文
wx_ai_bot.log              含聊天内容
wx_ai_bot_memory.json      含对话历史
wx_ai_bot_profiles.json    含联系人画像
.wxdb_cache/               解密后的数据库副本
```

**上传前务必跑**：

```bat
python tools/check_secrets.py --staged
```

它会检查密钥形态、wxid、手机号、邮箱、本机路径、被遗漏的敏感文件，
以及**人名黑名单**——正则查不出人名（人名没有格式特征），
所以要查人名得建 `.name_blocklist.txt`（已 gitignore）或加 `--names "张三,某群名"`。

> ⚠️ **如果密钥已经 push 过**：删文件没用，它还在 git 历史里 ——
> 必须**立刻去服务商后台吊销并重新生成**。
